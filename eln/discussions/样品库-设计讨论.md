# 样品库 — 设计讨论

> 在 ELN「样品」下新增样品库，用来维护真实产生的样品。现有样品池继续承担请验任务，不改成实物账。
>
> 状态：**第一轮讨论进行中（2026-09-22）**。下文是对需求的理解和待确认建议，未拍板，不改现有样品业务梳理。

## 1. 需求理解

现在 ELN 里叫「样品」的东西，实际是一条 **请验任务**：发起请验时同时生成请验单号、样品批号、条码，样品池按这个批号收样、分配、检测、登记结果。它不回答「这管东西还在谁手里、还剩多少、能不能再送一次」。

要补的是另一层：

| 要管的事 | 含义 |
| --- | --- |
| 真实样品 | 实验或注册对象实际产生出来、可以被再次找到的那一份 |
| 台账 | 领用、归还、送检、留样、销毁、状态变更都记成同一本流水 |
| 多次请验 | 一个样品可以发起多次请验，请验仍走现有样品池 |
| 来源 | 主要来自注册对象，或实验产出 |
| 简单的量 | 有数量，能扣、能留，不做仓库/库位/容器 |
| 实验里直接用 | 实验中可以选择并使用他人产出、仍有剩余量的样品 |

## 2. 和现有对象怎么分开

| 现有对象 | 它是什么 | 样品库不做什么 |
| --- | --- | --- |
| 样品池 / 请验单 / 样品批号 | 一次检测申请。样品批号在请验时生成，用来聚合这一次的检测项 | 不把请验单改成样品主数据 |
| 注册对象 | 这个物质/实体是什么 | 样品只引用它，不复制成第二条注册数据 |
| 实验产出 | 某次实验产出了什么 | 产出可以登记成样品；实验使用样品是另一笔台账 |
| 物料主数据 + 批次 + 库存 | 仓库里的目录、批次、容器、库位、领用出库 | 样品库不做入库单、仓库、库位、容器。资源管理里预留的仓库类别「样品库」是库存概念，和本次 ELN 样品库不是同一个东西 |

关系：

```text
注册对象 ──────► 样品（来源之一）
实验产出 ──────► 样品（来源之一）
样品 ──台账──► 领用 / 归还 / 送检 / 留样 / 销毁 / 状态变更 / 实验使用
样品 ──送检──► 请验单（可多次）──► 现有样品池（检测项、结果、报告）
```

## 3. 待确认建议

| # | 决策点 | 建议 | 理由 |
| - | --- | --- | --- |
| 1 | 菜单位置 | 放在 ELN「样品」下，与「样品池 / 我的请验 / 我的分析」并列，入口就叫样品库 | 用户从样品菜单找实物；样品池保持请验任务不变 |
| 2 | 样品是什么 | **一份可再找到的实物记录**：自己的样品编号、来源、初始量、剩余量、单位、状态、所属项目。不是注册对象，不是物料批次，不是请验单 | 「一个样品多次请验」要求样品比请验活得更长 |
| 3 | 编号 | **样品编号**由样品库生成。请验仍生成自己的请验单号和样品批号。请验单增加对样品的引用 | 现有「我的请验按样品批号聚合检测项」不用拆。样品批号继续表示这一次送检，不升格成实物编号 |
| 4 | 来源 | 两条：①引用一条注册对象；②引用一条实验产出。来源必填其一，只存引用和展示用的编号/名称，不把注册字段或实验字段搬进样品 | 样品库维护的是这份实物，不是再做一套主数据 |
| 5 | 台账 | 领用、归还、送检、留样、销毁、状态变更、实验使用，都是样品下的台账行：时间、操作人、数量、前后剩余量、备注。状态变更也走台账，不在台账外悄悄改 | 用户要求这些动作统一进台账 |
| 6 | 量 | 只保留初始量、剩余量、留样预留量、单位。可用量 = 剩余量 − 留样预留量。领用、送检、实验使用扣可用量；归还加回剩余量；销毁把剩余量清零。不做容器拆分，不做单位换算 | 「简单的量」。留样若只是个状态，留着的量仍会被领走 |
| 7 | 状态 | 样品整体状态：**可用、留样、已销毁、已用尽**。部分领用不把整份改成「已领用」，只记台账并减可用量。可用量到 0 变为已用尽。留样、销毁、以及用户手工状态变更记台账 | 有量之后，领用是数量动作，不是整份移交 |
| 8 | 送检 | 从样品台账发起请验 = 送检。写一条送检台账，并在现有请验流程上生成请验单，请验单指向该样品。送检量从可用量扣减。一个样品可有多张请验单 | 把「多次请验」接到现有样品池，不另做一套检测 |
| 9 | 实验中使用 | 实验记录里可以选择样品库中可用量 > 0 的样品，包括他人产出的。选定后记一条「实验使用」台账并扣量，实验记录留下样品编号 | 对应「直接使用其他人产出的样品产出物」 |
| 10 | 不做的范围 | 不做仓库、库位、容器、批次谱系、效期、审批流、与库存领用单的自动对账 | 这些是资源管理已经有的能力；本次只补实验侧的实物账 |

## 4. 按这个建议走时的两条主路径

**产出进入样品库**

```text
实验产出登记，或从注册对象手工登记
  → 生成样品（编号、来源、初始量=剩余量、状态=可用）
  → 台账首行：登记
```

**之后怎么被用掉**

```text
样品
  ├─ 领用 / 归还     改剩余量，状态仍为可用（除非可用量到 0）
  ├─ 留样           划出预留量，状态改为留样；预留量不可再领用、送检、实验使用
  ├─ 送检           扣送检量，生成请验单（可多次）→ 进入现有样品池
  ├─ 实验使用       他人或本人在实验里选用，扣量
  ├─ 销毁           剩余量清零，状态=已销毁
  └─ 状态变更       记台账，改状态
```

## 5. 这一轮需要先拍的问题

建议先拍 **#2 和 #6**：样品是不是「一份带剩余量的实物」，以及量是不是「可部分扣减、留样是预留量」。这两条定了，编号、请验和实验使用才有落点。

| # | 问题 | 不拍会怎样 |
| - | --- | --- |
| Q1 | 样品是一份带剩余量的实物，还是一次实验产出下的一个批（下面再拆成多份）？ | 决定要不要做拆分、子样品 |
| Q2 | 领用是扣一部分量，还是把整份样品交给某个人？ | 决定状态里有没有「已领用」 |
| Q3 | 送检量是消耗掉，还是先冻结、检测完有可能回来？ | 决定送检台账会不会有对应的归还 |
| Q4 | 实验产出是自动变成样品，还是产出时由用户选择「登记到样品库」？ | 决定样品从哪一刻开始存在 |
| Q5 | 没有实验产出、只有注册对象时，是否允许手工登记一份样品？ | 对应「来源主要来源于注册对象或实验产出」里的「或」 |
