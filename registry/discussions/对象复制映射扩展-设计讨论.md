# 对象复制映射维度扩展（对象 ↔ 物料主数据）— 设计讨论记录

> 对象复制的映射机制从"对象 → 对象"扩展到"对象 ↔ 物料主数据（物料类型）"。  
> 痛点：实验产物对象创建时需同步录入样品物料/库存相关信息，两侧共用字段（名称、批号、浓度、纯度、有效期、厂家、COA 等）重复填写，录入复杂且易错；统一两套数据模型则涉及物料主数据侧大量改造，代价不可接受。
>
> 状态：**第五轮讨论进行中（2026-09-16）**。9-15 决策主体已闭环并已写入正式功能设计说明；本轮收口文档内部矛盾，并继续讨论复制确认弹窗、自动复用与注册数据锚点、物料侧入口、单位映射。  
> 压力测试后补建议 **#23–#27**（与 #18–#22 一并待确认）。未确认前不改正式功能设计说明。

## 1. 已确认决策

| #  | 决策点     | 结论                                                                                          |
| -- | ------- | ------------------------------------------------------------------------------------------- |
| 1  | 映射配置位置  | **统一配置在对象上**（2026-09-15 更新）：对象的映射关系设置中并存两类映射——①**对象模型映射**（对象↔对象，原对象复制功能）；②**对象与物料信息映射**（对象↔物料主数据，本扩展）。物料类型侧不设配置入口，1:1 绑定约束不变（决策 #6） |
| 2  | 复制方向    | **双向均支持**：对象→物料主数据、物料主数据→对象                                                                 |
| 3  | 映射字段范围  | **仅基础信息 + 扩展信息，批次信息不映射**（2026-09-15 更新，替代原"批次字段作为普通字段参与映射"结论）：主数据层只映射物料类型的基础信息字段与扩展字段；批次相关内容（批号、有效期至、父细胞、序列图谱、检测状态、来源实验等批次字段）不属于主数据复制映射范围 |
| 4  | 主数据判重策略 | **已被决策 #15 替代**：原结论为"阻断并提示复用"；2026-09-15 改为命中唯一性校验后**自动复用、不新建**（见 #15） |
| 5  | 主数据编号规则 | **沿用现有规则**（2026-09-15 确认）：系统按编号规则自动生成，新增时支持修改；不继承源对象编号 |
| 6  | 映射数量关系  | **一个对象可配置多个不同物料类型的映射；但一个物料类型只能被一个对象的映射绑定**（物料类型侧一对一，全局唯一）                                   |
| 7  | 特殊字段映射  | **已消解（2026-09-15）**：批次信息不映射后，父细胞/关联序列/COA 等均属批次字段，出范围；化合物确认不参与映射。基础信息仅剩物料编号、注册数据（系统写入） |
| 8  | 溯源机制    | **注册数据锚点**（2026-09-16 澄清）：对象→主数据**新建**时，自动写入物料主数据"注册数据"字段指向源对象实体（需物料类型开启该字段）。不另建来源关联字段。**批号对应不属于复制映射**：批次信息不映射，批号若与源对象编号对齐，发生在后续产物入库/预入库登记，不在本次复制落库 |
| 9  | 入口与权限   | **2026-09-16 澄清（待确认）**：对象侧入口为列表/详情"复制到物料..."。物料侧**需要**反向入口（否则双向无法完成），放在主数据详情/列表"复制到对象..."，**不新增**资源管理菜单级权限，沿用「主数据查看 + 对象新增」。原"物料侧不做源侧推送入口"指的是不对齐库存菜单权限，不是取消反向复制入口 |
| 10 | 同公司约束   | **沿用**对象复制的前置约束：源对象与物料类型/主数据必须属于同一公司，跨公司禁止配置映射与复制 |
| 11 | 列表/选项类字段映射 | **同名选项自动匹配 + 不可匹配留空**（2026-09-15 确认）：对象下拉字段值与物料列表/选项字段候选值按名称自动匹配；匹配不上的值留空（必填项则阻断，用户弹窗补充） |
| 12 | 主数据→对象遇工作流 | **进"待审批"**（2026-09-15 确认）：目标对象开启工作流时，物料主数据→对象的复制入库同样走"待审批"临时状态，规则与对象复制一致 |
| 13 | 主数据初始状态与前置校验 | **默认"启用"**（2026-09-15 确认）；复制前置条件：物料类型需处于"已发布 + 启用"状态（与手动新增主数据校验一致） |
| 14 | 双向确认弹窗形态 | **延后至原型设计阶段确定**（2026-09-15 确认，本阶段不做决策） |
| 15 | 判重命中后的处理 | **自动复用，不新建**（2026-09-15 确认，细化决策 #4）：复制时命中物料类型"主数据唯一性校验"→ 不新建主数据，该入库物料**直接引用已有主数据**；源对象实体不受影响。即用户无需手动复用，系统自动挂接 |
| 16 | 只读扩展字段的复制写入 | **允许写入**（2026-09-15 确认）：物料扩展字段"是否只读"约束的是表单交互层（防用户手动编辑）；对象复制属于**新增初始化**场景，系统写入不受只读限制 |
| 17 | 字典变更与历史取值 | **老数据不清，新数据按最新匹配**（2026-09-15 确认）：扩展字段关联数据源（字典）变更后，既有主数据历史取值不清空（沿用既有约束）；复制新增的数据按最新字典选项进行文字匹配 |

## 2. 映射关系模型

```
（物料类型侧一对一约束）

对象 A ────映射1────► 物料类型 T1（细胞-XX）
       ────映射2────► 物料类型 T2（质粒-YY）     ← 一个对象可配多个物料类型
       ────映射3────► 物料类型 T3

对象 B ────映射4────► 物料类型 T4

物料类型 T1 ──已被 A 绑定──► 对象 B 不可再绑定 T1  ← 一个物料类型只能配一个对象
```

双向复制均基于同一套映射配置执行：

- **对象 → 物料主数据**：对象实体详情/列表"复制到..."，选择已配映射的物料类型，确认后在该物料类型下生成主数据
- **物料主数据 → 对象**：主数据详情/列表发起"复制到对象..."（入口形态随确认弹窗一并出原型），选择已配映射的对象，确认后在目标对象下生成新实体

## 3. 与原对象复制规则的差异对照

| 维度   | 对象 → 对象（原）               | 对象 ↔ 物料主数据（本扩展）                                     |
| ---- | ------------------------ | --------------------------------------------------- |
| 配置位置 | 目标对象-数据映射                | 对象的映射关系设置中并存"对象模型映射"与"对象与物料信息映射"两类（配置入口统一在对象上） |
| 映射字段 | 对象全部可映射字段                | **仅物料类型的基础信息 + 扩展信息**（批次信息、系统字段不映射） |
| 数量关系 | 多对一汇聚；同源同目标至多一套映射（单源单映射） | 对象 1:N 物料类型；物料类型 1:1 对象（物料类型侧唯一绑定）                  |
| 判重   | 纯新建，重复复制=多条，不判重          | 命中物料类型"主数据唯一性校验"（多字段组合）→ **自动复用已有主数据，不新建**（决策 #15） |
| 溯源   | 内置系统级"来源关联"字段+来源标签       | 新建时写入"注册数据"指向源实体；复用时不改已有主数据（本轮建议 #18）；批号不在复制职责内 |
| 编号   | 目标按自身名称规则重新编号，不继承源       | 主数据编号自动生成、新增时可修改（沿用现有规则，不继承源编号）                     |
| 校验   | 必填项（关键项）空则阻断             | 同左；命中主数据唯一性 → **自动复用、不新建**（#15），不是阻断新建 |
| 字段结构 | 双方均为对象模型，字段类型体系一致        | 物料类型侧字段为"基础信息（按业务类型）+扩展字段"，类型体系不同，兼容规则需适配 |

## 5. 两侧字段体系对照（依据：物料类型默认属性.md + Registry 科学数据注册.md）

### 5.1 物料类型侧字段类型体系与映射范围

物料类型默认属性中的字段类型：**文本、数值、时间、列表、附件、特殊、长文本、序列文件、人员选择**。

**映射范围（2026-09-15 确认）：仅基础信息 + 扩展信息。** 批次信息字段全部不参与映射。

**范围内（基础信息）的特殊字段**：

| 特殊字段 | 所属 | 含义 | 映射处理 |
| --- | --- | --- | --- |
| 物料编号 | 基础信息（所有类型） | 主数据编号，自动生成可编辑 | 系统自动生成，新增时可修改（决策 #5）；不作为映射行配置 |
| 注册数据 | 基础信息（所有类型） | 关联 Registry 注册实体（见 5.2） | 复制时系统自动写入，指向源对象实体（决策 #8） |
| 化合物 | 基础信息（普通物料） | 关联化合物库；与【注册数据】互斥（同类型只显示其一） | **不参与映射**（化合物为老业务，新业务中对象侧已支持化合物类型） |

**范围外（批次信息，全部不映射）**——以下特殊字段因批次出范围而自动消解：

| 字段 | 原待讨论问题 |
| --- | --- |
| 检测状态、批次号、有效期至、所属项目、来源实验 | 批次字段，出范围 |
| 父细胞/父质粒/父病毒/关联质粒/引物/特征基因 | 批次字段（原"关联递归"候选），出范围 |
| 序列图谱（序列文件） | 批次字段（原"序列内容文件级映射"候选），出范围 |
| COA/附件、供应商、货号 | 批次字段，出范围 |

范围外字段说明：批次相关内容在产物入库/预入库登记环节录入（走原有入库链路），不属于主数据复制映射的职责。

### 5.2 Registry 对象侧相关能力

- **注册数据字段（物料类型基础信息可选项，默认不显示）**：设为显示时，物料主数据支持选择 Registry 科学注册数据；**注册数据编号参与主数据的唯一校验**；选中后同步更新物料名称为"编号 (名称)"格式；普通物料中【化合物】与【注册数据】互斥——本扩展中**化合物字段不参与映射**（老业务，新业务对象侧已支持化合物），映射配置侧不受互斥影响
- **物料主数据入口**：物料库-物料配置-物料主数据、ELN-实验记录-产出入库模块
- **关联物料 tab（Registry 对象详情）**：与注册数据关联的物料在实体详情"关联物料"tab 显示库存信息（容器号、批次、物料编号、物料名称，支持搜索；默认不显示无剩余量物料）
- **主数据导入模板**：启用注册数据字段的物料类型，导入模板增加【注册对象】【注册数据】列（注册对象选择同公司对象，注册数据用户输入对象编号）

### 5.3 字段类型映射兼容矩阵（对象 → 物料主数据，仅基础信息+扩展信息）

| 物料侧字段类型 | 可接受的对象侧类型 | 处理方式 |
| --- | --- | --- |
| 文本/长文本 | 文本/数字/日期/下拉 | 转字符串 |
| 数值 | 数字 | 直接；文本需校验可转数值 |
| 时间 | 日期 | 按目标格式转换（基础信息中时间字段较少） |
| 列表 | 下拉/文本 | **同名选项自动匹配 + 不可匹配留空**（决策 #11）；列表来源为通用配置（可关联数据源字典） |
| 附件/图片 | 附件/图片 | 文件复制（图片为生物类基础信息字段） |
| 特殊-物料编号 | — | 系统自动生成（决策 #5），非映射行 |
| 特殊-注册数据 | — | 复制时系统自动写入指向源实体（决策 #8），非映射行 |
| 特殊-化合物 | — | 不可映射（老业务，排除） |

### 5.4 业务类型字段清单速查

7 种业务类型（普通物料/细胞/质粒/菌种/病毒/抗体/引物）的完整字段清单见《物料类型默认属性.md》。要点：

- 6 种生物类物料基础信息字段完全一致（7 个）：物料编号、物料名称、别名、注册数据、外文名称、生产厂家、图片
- 普通物料基础信息独有：规格型号、浓度、纯度、含量、化合物、级别
- 所有类型共享批次字段（5 个）：批次号、检测状态、有效期至、所属项目、来源实验
- 质粒字段最多（32 个），细胞最少（19 个）
- "来源实验"（列表）指向 ELN 实验记录，属批次字段，**不映射**（决策 #3）

### 5.5 扩展字段能力与对象字段的映射方案（依据：物料类型扩展字段配置 PRD）

物料类型扩展信息支持 **11 种字段类型**，通用配置项：字段名称（同类型内唯一）、是否只读、表单属性 key（全局唯一）、校验条件、必填项。其中复选框/单选框/下拉选择框支持"行数据 + 关联数据源"（绑定【通用配置】字典，选项随字典同步；不绑定则为手动固定选项）。

**对象字段 → 物料扩展字段兼容矩阵**：

| 物料扩展字段类型 | 可接受的对象侧类型 | 处理方式 |
| --- | --- | --- |
| 单行文本 | 文本/数字/日期/下拉 | 转字符串 |
| 多行文本 | 文本（多行优先）/文本 | 转字符串（换行保留） |
| 计数器 | 数字 | 直接；文本需校验可转数值；需满足最小值/最大值/小数位校验 |
| 滑块 | 数字 | 直接；需满足区间（最小/最大值）校验 |
| 开关按钮 | 勾选 | 布尔直搬 |
| 时间选择框 | 日期 | 按目标格式转换 |
| 单选框 | 下拉（单选） | 同名选项自动匹配 + 不可匹配留空（决策 #11） |
| 下拉选择框 | 下拉（单选） | 同名选项自动匹配 + 不可匹配留空（决策 #11） |
| 复选框 | 下拉（多选） | 逐值同名匹配；部分匹配则仅搬匹配项，全部不可匹配留空 |
| 图片 | 图片/附件 | 文件复制（图片格式） |
| 上传 | 附件 | 文件复制（多文件支持） |

**选项匹配的两种来源**（决策 #11 细化）：
- 扩展字段**关联数据源**（通用配置字典）：按字典当前选项与对象字段值同名匹配
- 扩展字段**手动行数据**（固定选项）：按固定选项与对象字段值同名匹配

**校验衔接**：复制写入需过扩展字段的校验条件（最大长度、正则、数值区间、步长等）与必填项约束——必填且映射不上时，沿用"阻断 + 弹窗补充"策略；非必填留空。

**遗留细节**（待讨论 #9、#10 → 已闭环为决策 #16、#17）：
- "是否只读"：复制属新增初始化，系统写入允许
- 字典变更：老数据不清空，新复制按最新选项文字匹配

### 6.2 本轮建议（待确认）

| 18 | 复用时是否改写已有主数据 | **不新建、不改写**（用词修正：复制不产生入库单，不是「库存挂接」）。命中唯一性 → 已有主数据字段保持原值（含已填的注册数据）；源对象也不改。提示「已存在主数据【编号】，未新建」。**空锚点可补写**：已有主数据注册数据为空且类型开启该字段 → 补写当前源对象（空→有，不是抢锚点）。关联物料 tab 只认主数据上的注册数据，复用不会凭空给当前对象多一条关联 | 覆盖已有注册数据会把对象 A 的锚点抢走；对象复制本身也无同步。复制与产物入库是两条链路 |
| 19 | 对象→主数据弹窗可改项 | **映射字段只读**；**注册数据只读**（系统写入）；**物料编号**按现有新增规则自动生成、允许改；**计量单位/小数位**只读带出。未映射的非只读必填项高亮可填；未映射非必填可填可空。物料名称见 #26。完整字段表见 6.6 | 对齐对象复制「映射只读 + 缺口手填」；主数据新增本就可以改编号 |
| 20 | 主数据→对象弹窗默认值 | **不从主数据继承部门/项目**（主数据层没有这两项）。部门=当前用户所属部门（必填，可改）；项目=空（可填）；分享人/可见范围/别名按对象手动注册默认（可见范围默认不勾选）。映射数据只读；目标对象开启工作流则提交后进待审批 | 物料主数据与注册实体的基础信息模型不同，硬继承会编造数据 |
| 21 | 物料侧入口 | **要做**：主数据详情/列表「复制到对象...」。不新增库存菜单权限；校验「主数据查看 + 目标对象新增」。仅「启用」主数据可作源。列表支持批量，逐条确认、逐条落库（与对象复制一致）；单条命中 #24 则该条失败、不影响其他条 | 没有入口则决策 #2 双向无法落地；#9 只约束权限模型 |
| 22 | 单位 | **只映射数值，不做换算**（资源管理自己也把单位换算放在后续迭代）。两层单位都只读带出、不作为映射行：①主数据计量单位/小数位←物料类型；②浓度/纯度/含量的字段级单位←该字段已配单位。对象侧若把单位写在文本里（如 "10 mg/mL"），不解析，按文本→数值规则失败则必填阻断/非必填留空 | 复制里做 mg/mL↔μM 会引入错误；与系统写入项一致 |

### 6.3 建议后的复制提交时序（对象→主数据）

```
仅「有效」对象可发起（建议 #25）
选目标物料类型 → 打开确认弹窗（预填映射 + 系统写入项）
   → 用户补缺口 / 改编号
   → 提交
   → 必填与类型校验（失败留在弹窗）
   → 按物料类型「主数据唯一性校验」判重（开启注册数据时该字段必须在校验集内，#23）
         ├─ 未命中：新建主数据，写入映射值 + 注册数据锚点，状态启用
         └─ 命中：不新建
               ├─ 已有注册数据为空：补写当前源对象（#18 空锚点例外）
               ├─ 已有注册数据=当前源：无动作，提示已存在【编号】
               └─ 已有注册数据=其他对象：不改写，提示已关联【对象A】，未新建
不生成入库单 / 不写批号
```

同一对象对同一物料类型再点一次复制：唯一性含注册数据时命中自己上次建的主数据 → 复用，不会复制出第二条（与对象→对象「重复复制=多条」不同）。

### 6.5 压力测试：#15「自动复用」不能当成入库挂接

#15 原文「该入库物料直接引用已有主数据」把两条链路写混了：

| 链路 | 产物 | 判重结果 |
| --- | --- | --- |
| 本功能：对象 → 物料主数据 | 一条主数据（目录项） | 命中则**不新建主数据** |
| 既有：产物入库 / 预入库登记 | 批次 + 容器库存 | 选已有主数据后填批次；**本次不做** |

注册数据是主数据上的 **1:1** 字段（一条主数据只能指向一个注册实体）。关联物料 tab 也只认这个字段。因此：

- 不改写已有注册数据（#18）时，对象 B 撞上对象 A 已生成的主数据 → B 的关联物料 tab **不会多出物料**
- 若允许 B 覆盖注册数据 → A 的锚点被抢走
- 对象侧没有「来源关联」可写到物料上；物料也不是对象实体，反向复制不能复用对象复制的来源关联字段

要让 #15 自动复用只命中「自己上次建的那条」，复制路径必须保证：开启注册数据时，**不同对象不会因名称/厂家撞车而复用同一条主数据**。这就是 #23。反向则必须处理「主数据已经有注册数据」——这就是 #24。

### 6.6 确认弹窗可改项清单（把 #14 从「延后」收到可评审表）

**对象 → 物料主数据**（形态对齐「主数据新增」，建议 #19）：

| 字段 | 可改 | 默认 / 规则 |
| --- | --- | --- |
| 物料编号 | 可改 | 按编号规则自动生成，不继承源对象编号（#5） |
| 注册数据 | 只读 | 系统写入当前源实体；类型未开启该字段则不展示 |
| 计量单位、计量小数位 | 只读 | 物料类型已配则带出 |
| 浓度/纯度/含量的字段单位 | 只读 | 有字段级单位则带出，不映射、不换算（#22） |
| 已映射的基础/扩展字段 | 只读 | 映射转换后的值 |
| 未映射必填 | 可填 | 空，高亮；不补则提交阻断 |
| 未映射非必填 | 可填可空 | 空 |
| 物料名称 | 见 #26 | 开启注册数据：跟「编号 (名称)」只读同步；未开启：已映射只读，未映射可填 |

**物料主数据 → 对象**（形态对齐「手动注册」，建议 #20）：

| 字段 | 可改 | 默认 / 规则 |
| --- | --- | --- |
| 编号 / 名称 | 只读（系统生成） | 按目标对象名称规则；开启工作流则先用临时编号 |
| 部门 | 可改 | **当前用户所属部门**（必填），不从主数据继承 |
| 项目 | 可改 | **空** |
| 分享人、可见范围、别名 | 可改 | 与手动注册默认一致（可见范围默认不勾选） |
| 已映射字段 | 只读 | 映射转换后的值 |
| 未映射必填 | 可填 | 空，高亮 |
| 来源关联 | 不写 | 来源关联只服务对象↔对象；本方向溯源靠主数据上的注册数据（#24 回写） |

### 6.7 本轮补建议（待确认）

| # | 决策点 | 建议结论 | 理由 |
| - | --- | --- | --- |
| 23 | 复制路径的判重键 | **不另做一套判重**。开启「注册数据」的物料类型：保存对象↔物料映射时，**必须已把「注册数据」纳入主数据唯一校验**，否则不允许保存映射。关闭注册数据：沿用类型既有唯一性即可（无锚点，共享目录项合理） | 手动新增与复制必须同一把尺子。若只在复制时偷偷并上注册数据，会造出「手动新增会判重失败」的主数据。强制纳入后，自动复用只会发生在同一对象再次复制 |
| 24 | 主数据→对象时注册数据怎么处理 | **已有注册数据 → 阻断**，提示「该主数据已关联【对象编号】」，不新建对象、不覆盖锚点。**注册数据为空 → 新建对象，并回写注册数据**指向新实体。不写对象侧来源关联 | 1:1 锚点的反向。典型场景是库存先有主数据、Registry 后补注册；已关联再复制会得到第二条注册实体，和关联物料 tab 对不上 |
| 25 | 谁能当复制源 | 对象→物料：仅 **有效** 实体（待审批/审批中/停用不行），对齐对象复制。物料→对象：仅 **启用** 主数据（已有结论）。命中已**禁用**主数据：仍不新建（唯一性不允许第二条），提示「已存在但已禁用【编号】」 | 临时编号不能写成注册数据锚点；禁用主数据也不能靠复制再造一条 |
| 26 | 物料名称 vs 注册数据同步 | 类型开启注册数据时，**物料名称不作为有效映射行**（配置表可灰显/过滤）：落库名称=「源对象编号 (源对象名称)」，改编号后跟既有规则走。未开启注册数据时，名称可映射，规则与其他文本字段相同 | 手动新增选注册数据本来就会覆盖物料名称；映射再配名称只会和系统规则打架 |
| 27 | 反向有没有对象侧判重 | **没有**。对象没有主数据那种组合唯一性；主数据→对象每次都是新建，规则同对象→对象。同一主数据第二次再复制会被 #24 挡住（此时已有注册数据） | 避免做成「反向也自动复用对象」；对象复制已明确重复复制=多条 |

**反向提交时序（主数据→对象）**：

```
仅「启用」主数据可发起（#25）
已有注册数据？ ──是──► 阻断，提示已关联【对象编号】（#24）
                └──否──► 打开确认弹窗（映射只读 + 部门/项目按 #20）
                         → 补缺口 → 提交 → 必填校验
                         → 按目标名称规则新建对象（工作流则待审批）
                         → 回写主数据.注册数据 = 新对象（#24）
```
